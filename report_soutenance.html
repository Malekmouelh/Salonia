SECTION 1 : VUE D'ENSEMBLE ARCHITECTURALE & NON-RÉGRESSION

1.1 Positionnement dans l'App Router Next.js

Le Module 1 remplit le double rôle stratégique de la plateforme Salonia en séparant strictement l'espace d'administration et l'espace public :

  • Espace Administration (/dashboard/vitrine) : Accessible uniquement aux propriétaires de salon (Role.OWNER). Piloté par des Server Actions Next.js avec validation Zod, audit log système et aperçu réactif en temps réel.
  • Espace Public (/salon/[slug] et /salon/[slug]/[centerId]) : Vitrine web haute performance générée en Server-Side Rendering (SSR), accessible sans authentification, bilingue (Français/Arabe RTL), optimisée pour le SEO dynamique et les réseaux sociaux.

1.2 Stratégie d'Isolation Stricte & Non-Régression Collaborateur

Pour garantir l'intégrité du code de l'équipe et éviter tout conflit de merge ou de build :

  • Modifications Purement Additives sur le Cœur (lib/models/core.ts) : L'OrganizationSchema existant a été complété par deux sous-documents stricts avec valeurs par défaut neutres : theme et features. Tous les tests existants des collègues sont demeurés 100% verts.
  • Collections Dédiées et Étanches (lib/models/vitrine.ts) : Les avis clients (Review) et les réalisations du portfolio (Realization) disposent de collections isolées avec clés étrangères et index composés (organizationId, createdAt).
  • Namespace Isolé sous lib/vitrine/ : Toute la logique métier (schémas Zod, algorithme QR Code vectoriel, services d'écriture) est cloisonnée sans interférence.
  • Server Actions Fermées (app/actions/vitrine.ts) : Aucune route d'API partagée n'a été altérée.

1.3 Alignement avec les Standards Académiques du Cours

  • Mongoose Singleton Pattern (lib/db.ts) : Instance unique de connexion globale réutilisée pour neutraliser les fuites de connexions en environnement Serverless / Fast-Refresh.
  • Server Actions ('use server') : Remplacement des routes REST par des appels RPC directs sécurisés nativement contre les attaques CSRF.
  • Tailwind CSS 4 Tokens & Variables CSS : Thème dynamique piloté sans recompilation via --vitrine-primary, --vitrine-secondary et --font-display.
  • Algorithme Vectoriel Pure TypeScript : Moteur QR Code autonome (polynômes de Reed-Solomon et corps de Galois GF(256)) à zéro dépendance npm vulnérable.

SECTION 2 : DÉTAIL TECHNIQUE EXHAUSTIF PAR EXIGENCE (F1.1 À F1.6)

F1.1 : Personnalisation du Design & Identité Visuelle Priorité E

1. Rôle Fonctionnel : Permet au salon de configurer son identité de luxe : logo, bannière panoramique, palette de couleurs personnalisée ou presets signature (Rose Gold, Or Impérial), sélection de polices de prestige et mode sombre/clair.

2. Flux Technique : theme-editor.tsx (état local) → updateThemeAction() → ThemeConfigSchema.parse() → MongoDB updateTheme() avec audit log → revalidatePath → Toast et réinitialisation de formulaire.

3. Contrôle de Saisie & Sécurité :

  • Client : Sélecteurs natifs hexadécimaux, maxLength={140} (slogan) et maxLength={1000} (description). Upload d'image limité à 2 Mo en WebP/Base64.
  • Serveur (Zod) : primaryColor: z.string().regex(/^#([0-9a-fA-F]{3}|[0-9a-fA-F]{6})$/), fontFamily: z.enum([...]). RBAC : requireRole(Role.OWNER).
Q. Encadrant : Pourquoi utiliser des variables CSS en ligne plutôt qu'une balise <style> générée dynamiquement ?
R. Étudiante : L'injection de chaînes CSS brutes dans une balise <style> ouvre la porte à des failles de CSS Injection / exfiltration de données. L'application via l'attribut React style de variables CSS validées par regex hexadécimale garantit que la valeur est strictement traitée comme un token de couleur, sans risque XSS.

F1.2 : Activation / Désactivation des Fonctionnalités Priorité E

1. Rôle Fonctionnel : Permet au salon d'adapter sa vitrine à son modèle d'affaires (activation ou masquage en 1 clic : paiement en ligne, packs, fidélité, avis, galerie).

2. Flux Technique : feature-toggles.tsx → updateFeaturesAction() → FeaturesConfigSchema (prétraitement booléen) → écriture MongoDB $set: { features } → revalidatePath masquant immédiatement les sections sur la vitrine publique.

3. Contrôle de Saisie & Sécurité : Prétraitement Zod convertissant "true" | "on" en booléen strict. Élimination automatique (strip) de toute clé non autorisée par Zod.

Q. Encadrant : Si un attaquant injecte un champ 'isAdmin: true' dans la requête, que se passe-t-il ?
R. Étudiante : Zod filtre par défaut toutes les propriétés non définies dans FeaturesConfigSchema. Le champ injecté est purement ignoré et la mutation est protégée par la vérification de session du propriétaire.

F1.3 : Vitrine Publique et QR Code Partageables Priorité E

1. Rôle Fonctionnel : Vitrine publique accessible à /salon/[slug] et /salon/[slug]/[centerId] avec modal de partage en 1 clic et génération de QR Code vectoriel sans dépendance externe.

2. Flux Technique : Server Component → getPublicSalonShowcase(slug) en requête Mongoose unique .lean() → Rendu SSR avec métadonnées OpenGraph → Clic sur « Partager & QR » générant le flux SVG en mémoire via generateQrCodeSvg().

3. Algorithme QR Code : Implémentation pure en TypeScript des polynômes de Reed-Solomon (correction d'erreurs Niveau M) et de la matrice binaire de Galois GF(256). Sortie en balises SVG vectorielles haute résolution.

Q. Encadrant : Pourquoi avoir codé votre propre générateur QR Code au lieu d'utiliser un package npm ?
R. Étudiante : 1) Pour la sécurité logicielle (zéro risque d'attaque de chaîne d'approvisionnement npm). 2) Pour la performance : moins de 6 Ko, aucun moteur Canvas lourd côté serveur, et un rendu SVG vectoriel imprimable sans pixellisation.

F1.4 : Studio d'Invitations & Affiches Réseaux Sociaux Priorité E

1. Rôle Fonctionnel : Génération instantanée d'affiches publicitaires de luxe au format Story Instagram (9:16 - 1080x1920) et Post Carré (1:1 - 1080x1080) avec QR Code incrusté, téléchargeables en PNG.

2. Flux Technique : invitation-studio.tsx → Rendu Canvas HTML5 2D haute définition à 300 DPI virtuels (dégradés radiaux or champagne, masquage circulaire de photo ctx.clip(), typographie ombrée) → Export via canvas.toBlob() → Téléchargement direct.

3. Sécurité Canvas (CORS) : Encodage des photos uploadées en Data-URLs Base64 locales pour empêcher le blocage de sécurité « Tainted Canvas » lors de l'export PNG.

Q. Encadrant : Pourquoi générer l'image côté client via Canvas plutôt que côté serveur avec Puppeteer ou Sharp ?
R. Étudiante : Le calcul graphique 2D est déporté sur le processeur/GPU client, épargnant la RAM et le CPU du serveur. De plus, la cliente bénéficie d'un aperçu et d'un téléchargement instantanés à zéro latence réseau.

F1.5 : Galerie de Réalisations & Avis Clients Vérifiés Priorité I

1. Rôle Fonctionnel : Preuve sociale et portfolio métier : soumission d'avis de 1 à 5 étoiles avec note moyenne calculée, et galerie photos filtrable par catégorie avec visionneuse agrandie (lightbox).

2. Flux Technique & Optimistic UI : createRealizationAction() persiste dans MongoDB → Mise à jour optimiste locale immédiate dans l'état React (la réalisation apparaît en tête de liste sans recharger la page F5) → Toast vert de confirmation.

3. Contrôle de Saisie (Zod) : rating: z.coerce.number().int().min(1).max(5), comment: z.string().min(3).max(500). Protection XSS native par échappement React JSX.

Q. Encadrant : Comment assurez-vous la rapidité de calcul de la moyenne si le salon possède des milliers d'avis ?
R. Étudiante : La collection est indexée sur { organizationId: 1, createdAt: -1 } et la requête n'extrait que le champ numérique rating via projection .lean(), ou via pipeline d'agrégation MongoDB $group avec $avg directement dans le moteur de base de données.

F1.6 : Interface Bilingue Français / Arabe avec Support RTL Priorité I

1. Rôle Fonctionnel : Basculement complet de l'interface en Arabe ou Français : inversion de la direction de lecture (droite à gauche - RTL), inversion des icônes directionnelles et typographies arabes adaptées (Cairo, Amiri, Tajawal).

2. Flux Technique : Script bloquant inline LANG_BOOT_SCRIPT dans <head> → Détection du cookie salonia_lang → Application de dir="rtl" avant le premier rendu HTML (Anti-FOUC) → Hook useI18n() et dictionnaire lib/i18n-ar.ts.

3. Classes Logiques CSS : Utilisation des propriétés CSS logiques start-, end-, ps-, pe- et de la classe Tailwind rtl:-scale-x-100 pour inverser automatiquement les flèches.

Q. Encadrant : Comment évitez-vous le clignotement visuel (FOUC) lors du chargement en langue Arabe ?
R. Étudiante : Grâce au LANG_BOOT_SCRIPT injecté dans le <head> HTML. Il s'exécute de façon synchrone avant le parsing du corps de la page, définissant dir="rtl" et lang="ar" immédiatement avant le premier affichage graphique.
